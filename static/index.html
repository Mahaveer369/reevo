    1. Mathematical Audit of Upstream ReEvo TSP-ACO (problems/tsp_aco/test.ipynb)

    Why static distance-matrix priors η̂(D) show mixed results when paired with MMAS + Candidate-Restricted 2-Opt.

    Dead-Code Algebraic Proof in heuristics_reevo

    In /problems/tsp_aco/test.ipynb (lines 20–42), the ReEvo-generated function computes correlation_matrix = np.corrcoef(edge_attr_norm.T) (O(n3) cost) and sets: 

    heuristic_values[i][j] = np.exp(
    -8 * edge_attr_norm[i][j] * correlation_matrix[j][j]
)

    Because the diagonal of any Pearson correlation matrix satisfies corrjj ≡ 1.0, the entire correlation matrix computation is a mathematical no-op. The heuristic reduces strictly to a column-standardized power-law transformation of inverse distance: 

    eta_hat[i, j] = exp(8 * mu_j / sigma_j) * (1 + d[i, j]) ** (-8 / sigma_j)

    Why 2-Opt Absorbs Static Priors (and Why JSSP Differs)

    • Local Search Basin Projection: In TSP, running 2-opt after ant tour construction projects every sampled tour onto a 2-opt local minimum. A static matrix η̂(D) cannot adapt to partial tour constraints; over-sharpening η̂(D) collapses ant diversity and causes premature MMAS stagnation.
    • Top-5 Candidate Pruning Trade-Off: Restricting 2-opt to the top-5 nearest neighbors reduces complexity from O(n2) to O(5n) (explaining large runtime speedups), but truncates valid improving moves on clustered TSPLIB instances.
    • Why JSSP Resolves This: In JSSP, conflict sets C arise dynamically as machine queues and job ready times evolve. Furthermore, restricting JSSP local search to Critical-Path Block Swaps (N1 / N5) is mathematically exact because non-critical swaps can never reduce Cmax.
